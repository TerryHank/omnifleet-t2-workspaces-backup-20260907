下面固定为今后所有多机协同工程的统一规范，不再针对某个框架做对比。建议命名为：

# 多机器人协同功能规范 MSC-V1

## 1. 协同成员管理

| 编号 | 规范要求 | 验收标准 |
|---|---|---|
| MSC-01 | 每辆车具有唯一机器人 ID | 不允许 ID、命名空间或状态数据冲突 |
| MSC-02 | 维护在线机器人列表 | 能实时显示在线、离线、故障、掉队状态 |
| MSC-03 | 机器人周期性发送心跳 | 超时后必须自动标记失联 |
| MSC-04 | 支持成员加入和退出 | 成员变化不能导致整个协调器崩溃 |
| MSC-05 | 汇总所有机器人状态 | 协调器能获得各车位姿、速度、任务和健康状态 |

## 2. 协同任务管理

| 编号 | 规范要求 | 验收标准 |
|---|---|---|
| MSC-06 | 支持整队任务启动 | 一条指令启动整个车队任务 |
| MSC-07 | 支持整队暂停和继续 | 暂停后所有车辆进入可确认的安全状态 |
| MSC-08 | 支持整队取消 | 取消后不得继续发送旧任务目标 |
| MSC-09 | 支持整队安全停止 | 所有车辆实测速度低于停车阈值 |
| MSC-10 | 具有明确任务阶段 | 能查询当前阶段、执行进度和失败原因 |
| MSC-11 | 支持多航点协同任务 | 航点自动连续执行，不依赖人工逐点点击 |
| MSC-12 | 防止重复任务 | 同一个任务不得被重复启动或重复执行 |

统一任务状态机：

```text
IDLE
  ↓
PRECHECK
  ↓
FORMING
  ↓
EXECUTING
  ├── PAUSED
  ├── DEGRADED
  ├── RECOVERING
  └── ABORTING
  ↓
REGROUPING
  ↓
STOPPING
  ↓
COMPLETED / FAILED
```

## 3. 队形协同

| 编号 | 规范要求 | 验收标准 |
|---|---|---|
| MSC-13 | 支持指定队形 | 至少支持纵队、横队和三角队形 |
| MSC-14 | 支持队形形成 | 车辆能从任意初始位置进入目标队形 |
| MSC-15 | 支持动态队形保持 | 领车运动时，跟车持续更新目标 |
| MSC-16 | 使用相对位姿描述队形 | 跟车目标由领车位姿和队形偏移计算 |
| MSC-17 | 支持队形误差监控 | 持续计算每辆车的位置和航向误差 |
| MSC-18 | 支持队形收缩、展开和切换 | 切换过程中不得发生车间碰撞 |
| MSC-19 | 支持任务结束后的重组 | 到达终点后形成指定停车队形 |

队形目标统一表示为：

```text
跟车目标 = 领车当前位姿 ⊕ 跟车相对偏移
```

## 4. 领车—跟车协同

| 编号 | 规范要求 | 验收标准 |
|---|---|---|
| MSC-20 | 明确当前领车 | 所有成员对领车 ID 的认知一致 |
| MSC-21 | 领车负责主任务路径 | 航点和任务进度以领车任务为主线 |
| MSC-22 | 跟车持续跟踪相对目标 | 领车运动时不需要人工重复下发目标 |
| MSC-23 | 跟车目标更新限频 | 防止频繁取消和重复提交导航目标 |
| MSC-24 | 支持动态更换领车 | 原领车故障后可选举或指定新领车 |
| MSC-25 | 换领车后重新计算队形 | 队形参考系必须自动切换到新领车 |

## 5. 车间安全协同

| 编号 | 规范要求 | 验收标准 |
|---|---|---|
| MSC-26 | 设置最小车间距离 | 任意两车不得小于安全距离 |
| MSC-27 | 预测车辆冲突 | 根据位置和速度计算潜在碰撞 |
| MSC-28 | 设置安全过滤层 | 危险指令必须被限速、修改或拒绝 |
| MSC-29 | 跟车目标不能落入其他车辆包络 | 目标生成阶段就应避免相互占位 |
| MSC-30 | 停车时保持安全间距 | 急停不能导致后车追尾 |
| MSC-31 | 协同安全优先于队形精度 | 无法同时满足时允许临时破坏队形 |

## 6. 编队整体避障

| 编号 | 规范要求 | 验收标准 |
|---|---|---|
| MSC-32 | 判断整体队形能否通过 | 不能只判断单车能否通过 |
| MSC-33 | 障碍物出现时统一协调 | 不允许每辆车完全独立抢行 |
| MSC-34 | 支持临时队形变换 | 窄通道可由三角形切换为纵队 |
| MSC-35 | 支持临时解散与重组 | 必要时单车依次通过，之后恢复队形 |
| MSC-36 | 领车受阻时通知全队 | 跟车应减速、等待或重新规划 |
| MSC-37 | 跟车受阻时协调处理 | 领车不能无限远离掉队车辆 |

推荐处理顺序：

```text
检测障碍
  ↓
判断编队整体能否通过
  ├── 可以：保持队形通过
  ├── 较窄：收缩或切换队形
  ├── 无法保持：临时解散并依次通过
  └── 无路可走：整队停车或重新规划
```

## 7. 路径与交通协调

| 编号 | 规范要求 | 验收标准 |
|---|---|---|
| MSC-38 | 检测多车路径冲突 | 能识别时间和空间上的路径交叉 |
| MSC-39 | 设置通行优先级 | 冲突时必须明确谁先行、谁等待 |
| MSC-40 | 支持窄通道互斥 | 同一窄通道不能被冲突车辆同时占用 |
| MSC-41 | 支持等待点和避让点 | 车辆可以在安全区域等待 |
| MSC-42 | 具有死锁检测 | 多车互相等待超过阈值时触发恢复 |
| MSC-43 | 具有死锁解除策略 | 支持后退、重新规划、释放资源或调整优先级 |

## 8. 掉队、失联与故障恢复

| 编号 | 规范要求 | 验收标准 |
|---|---|---|
| MSC-44 | 检测掉队 | 队形误差持续超限时标记掉队 |
| MSC-45 | 检测通信失联 | 心跳或状态超过规定时间未更新即触发 |
| MSC-46 | 检测车辆故障 | 导航失败、定位异常、无法运动均需上报 |
| MSC-47 | 失联后进入安全状态 | 根据任务配置整队减速、停车或降级运行 |
| MSC-48 | 支持掉队车辆归队 | 恢复后先进入安全汇合点，再加入队形 |
| MSC-49 | 支持故障车辆退出 | 故障车辆退出后其余车辆可以继续任务 |
| MSC-50 | 支持队形降级重构 | 三车失去一车后可切换为两车队形 |
| MSC-51 | 恢复过程防止重复执行任务 | 恢复后不得重新执行已经完成的航点 |

## 9. 多车任务分配

| 编号 | 规范要求 | 验收标准 |
|---|---|---|
| MSC-52 | 支持任务分配 | 能将不同目标分配给不同车辆 |
| MSC-53 | 支持能力约束 | 根据车辆类型、负载和可用状态分配 |
| MSC-54 | 支持距离和成本评估 | 优先分配给综合成本较低的车辆 |
| MSC-55 | 支持任务优先级 | 高优先级任务可以优先执行 |
| MSC-56 | 支持任务重新分配 | 车辆故障后未完成任务可以转交 |
| MSC-57 | 防止任务重复认领 | 同一任务只能由规定数量的车辆执行 |

如果当前只做固定编队任务，MSC-52～MSC-57 可以作为第二阶段，但接口应提前保留。

## 10. 协同控制权

| 编号 | 规范要求 | 验收标准 |
|---|---|---|
| MSC-58 | 每辆车同一时刻只有一个控制源 | 不允许多个节点同时竞争速度控制 |
| MSC-59 | 定义控制优先级 | 急停高于人工遥控，高于协同控制，高于普通导航 |
| MSC-60 | 切换控制模式时清除旧任务 | 旧目标和旧速度命令不得继续执行 |
| MSC-61 | 人工接管必须通知协调器 | 协调器不得继续把被接管车辆视为正常跟车 |
| MSC-62 | 恢复自动控制前进行状态检查 | 位姿、速度和任务状态必须重新同步 |

推荐控制优先级：

```text
急停
  >
安全过滤器
  >
人工接管
  >
协同控制器
  >
单车导航控制器
```

## 统一验收场景

以后每套多机协同工程至少执行以下测试：

1. 三车从不同位置形成三角形。
2. 领车自动连续执行不少于三个航点。
3. 跟车全程动态保持相对位置。
4. 在路径中放置静态障碍物。
5. 加入横穿的动态障碍物。
6. 让一辆跟车暂时受阻并测试归队。
7. 模拟一辆车通信失联。
8. 模拟领车故障并切换领车。
9. 测试窄通道队形切换。
10. 测试两车路径冲突和优先通行。
11. 任务取消后确认所有车辆停止。
12. 自动输出验收报告和失败原因。

## 最终通过条件

一套工程只有同时满足以下条件，才称为“多机协同闭环完成”：

```text
任务能够统一启动
+ 多车能够形成并保持队形
+ 领车能够自动完成多航点
+ 车间不会发生碰撞
+ 障碍出现时能够协同处理
+ 掉队车辆能够恢复
+ 失联车辆能够被安全处理
+ 冲突和死锁能够解除
+ 任务可暂停、取消和停止
+ 最终状态由实际测量确认
+ 全流程能够自动回归并生成报告
```

今后可以直接使用编号进行要求和验收，例如：

```text
本版本完成 MSC-01～MSC-43；
下一版本补充 MSC-44～MSC-51；
MSC-52～MSC-57 暂不纳入固定编队任务；
最终必须通过12项统一验收场景。
```
