# OmniFleet T2 操作指南（实际操作流程版）

按"从零开始怎么操作这台车"整理：开机 → 自检 → 连界面 → 建图 / 导航 → 参数实验 → 停机。
所有命令均与 113 车（192.168.3.113）2026-09-07 实际运行的启动文件、systemd 服务、Foxglove 白名单核对过；整理过程只读，未改动任何配置。
配套文档：《T2实践课程操作指南.md》（按北理工 9 个问题整理，本指南第 9 节有索引）。

---

## 0. 流程总览

```
上电 → 常驻服务自启 → 开机自检(robot_doctor) → 连 Foxglove
   ├─ 流程A：建图（MOLA mapping → 遥控走图 → /map_save 保存）
   └─ 流程B：导航（MOLA slam_navigation 先跑 → Nav2 → 拉初始位姿 → 发目标点）
        └─ 课上实验：Foxglove 调 3 个白名单参数
停止：取消目标 → 停 Nav2 → Ctrl+C 停 MOLA → 断电
```

**架构要点（先记住这三句）**：
1. 底盘、雷达、相机、Foxglove 等由 **systemd 常驻服务**管理，开机自动运行，不需要手动起；
2. **MOLA（定位建图）和 Nav2（导航）是手动启动的**，顺序必须是：先 MOLA，后 Nav2（导航服务单元里写明 "start MOLA first"）；
3. 终端操作前必须先 source 环境，且 **ROS_DOMAIN_ID=73**。

---

## 1. 开机与准备

1. 车辆平放，周围 1 m 无障碍，确认随手可断电；上电。
2. 电脑连车载路由器 WiFi，确认连通：
   ```bash
   ping -c 5 192.168.3.113
   ```
3. SSH 登录并准备环境（每条命令前都要有这四行）：
   ```bash
   ssh iecme@192.168.3.113
   source /opt/ros/humble/setup.bash
   source /home/iecme/workspace/hardware_drivers_ws/install/setup.bash
   source /home/iecme/workspace/omnifleet_t2_ws/install/setup.bash
   export ROS_DOMAIN_ID=73
   ```
4. 确认常驻服务全部 active（开机自启，无需手动启动）：
   ```bash
   systemctl is-active omnifleet-t2-chassis.service omnifleet-t2-airy.service \
     omnifleet-t2-description.service omnifleet-t2-orbbec-camera.service \
     omnifleet-t2-foxglove.service omnifleet-t2-waypoints.service \
     omnifleet-t2-nav2-parameters.service omnifleet-t2-dsh-diagnostics.service
   ```
   全部输出 `active` 才算就绪。

## 2. 操作前自检（约 2 分钟，全只读）

```bash
ros2 run omnifleet_bringup robot_doctor        # 一键体检，全部 PASS 再继续
ros2 topic echo /voltage/display --once        # 电池电压
ros2 topic hz /rslidar_points                  # 点云约 5–9 Hz，Ctrl+C 退出
ros2 topic hz /odom                            # 里程计约 10 Hz，Ctrl+C 退出
```

任何一项 FAIL：先按第 9 节索引排查，不要带病跑车。

---

## 3. 连接可视化界面（Foxglove）

1. 电脑打开 Foxglove Studio → Open connection → 填 `ws://192.168.3.113:8765`；
2. 选择 **T2 专用布局**（五面板：点云、车模、电压、IMU、/odom；另有地图与代价地图）；固定参考系为 `odom`，导航启动后可切 `map`；
3. 界面上可以直接做（白名单已放行）：
   - **2D Pose Estimate** → 发 `/initialpose` 设初始位姿；
   - **2D Goal Pose** → 发 `/goal_pose` 导航目标；
   - Parameters 面板 → 调膨胀半径等白名单参数（见第 7 节）；
   - 发布 `/controller_selector`、`/planner_selector` 切换控制器/规划器；
   - 航点话题 `/omnifleet_t2/waypoints/*`（见第 6 节）。
4. **当前限制**：Foxglove 无法遥控车速——`/cmd_vel_teleop` 现无订阅者，速度话题也未进白名单。遥控走车用**随车实体遥控器**（见第 4 节）。

（rosbridge 9090 只监听车端本机，供车上的工具使用，远程一律走 Foxglove 8765。）

## 4. 流程 A：建图

**第 1 步：把车摆到地图原点**（关键！建图起点就是后续导航的原点，车没摆好会导致初始定位不准）。

**第 2 步：启动 MOLA 建图**（SSH 终端里）：

```bash
cd /home/iecme/workspace/omnifleet_t2_ws
ros2 launch omnifleet_bringup production.launch.py \
  backend:=mola map_id:=active \
  map_dir:=/var/lib/omnifleet_t2/maps
```

**第 3 步：验证建图已工作**（另开一个 source 过的终端）：

```bash
ros2 topic echo /map --field info --once       # 有地图元信息输出
ros2 run tf2_ros tf2_echo map base_link        # 有位姿输出
```

Foxglove 里应能看到 `/map` 栅格随雷达扫描增长。

**第 4 步：遥控走图**：
- 用**随车实体遥控器**低速遥控车辆走遍需要建图的区域；
- 转弯放慢，避免定位跳变；回到原点附近结束；
- 备用方式（教员操作，注意安全，随时准备断电）：
  ```bash
  ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist \
    "{linear: {x: 0.1}, angular: {z: 0.0}}"     # 示例：0.1 m/s 直行；停止用 Ctrl+C 并立即发零速
  ```

**第 5 步：保存地图**：

```bash
ros2 service call /map_save std_srvs/srv/Trigger
```

或在航点面板点保存（第 6 节）。地图工件保存到 `/var/lib/omnifleet_t2/maps/<map_id>/`（MOLA 模式为 `local_map.mm`）。

**第 6 步**：在启动终端 `Ctrl+C` 结束建图。

## 5. 流程 B：导航

**第 1 步：先启动 MOLA（用已保存地图定位）**：

```bash
cd /home/iecme/workspace/omnifleet_t2_ws
ros2 launch omnifleet_bringup robot.launch.py \
  operation:=slam_navigation localization_backend:=mola \
  map_id:=active map_dir:=/var/lib/omnifleet_t2/maps \
  start_airy:=false use_camera:=false start_description:=false
```

验证：`ros2 run tf2_ros tf2_echo map base_link` 有输出。

**第 2 步：再启动 Nav2**（二选一）：

```bash
sudo systemctl start omnifleet-t2-navigation.service   # 推荐（后台运行）
# 或前台：ros2 launch omnifleet_bringup production_nav2.launch.py
```

> 注：如果 `ros2 node list` 里已经有 /bt_navigator、/controller_server，说明导航栈已在运行（例如现场教学演示中），跳过第 1、2 步即可。

**第 3 步：验证导航栈就绪**：

```bash
ros2 lifecycle get /bt_navigator       # 预期 active
ros2 lifecycle get /planner_server     # 预期 active
ros2 lifecycle get /controller_server  # 预期 active
```

**第 4 步：设初始位姿**：Foxglove/RViz 用 **2D Pose Estimate** 在地图上按车辆真实位置和朝向拉一次（车摆在原点附近时通常自动可用）。

**第 5 步：发导航目标**：
- Foxglove/RViz **2D Goal Pose** 点目标位姿；或
- 航点面板 `navigate_to`（第 6 节）。

**第 6 步：观察运行**：`/plan`（全局路径）、`/local_plan`（局部路径）、Local Costmap 膨胀圈、published_footprint；车辆会以 DWB 限速（当前 max_vel_x=0.1 m/s，慢是正常的）行驶。

**切换控制器/规划器（课堂演示用）**：向 `/controller_selector` 发 String：`FollowPath`（DWB，默认）/ `FollowPathRPP` / `FollowPathMPPI`；向 `/planner_selector` 发：`GridBased`（Smac2D，默认）/ `GridNavFn` / `GridThetaStar`。

## 6. 航点面板（语义航点）

- 后台桥接 `omnifleet_t2_waypoint_ui` 已随 `omnifleet-t2-waypoints.service` 常驻；
- 操作面板是 tkinter 图形界面，需在**车端接显示器**或 **SSH X11 转发**（`ssh -X`）下启动：
  ```bash
  ros2 launch omnifleet_waypoint_ui waypoint_ui_with_panel.launch.py
  ```
- 面板功能：开始/停止录制航点、撤销、清空、重命名、导航到指定航点；
- 路线持久化文件：`/var/lib/omnifleet_t2/missions/waypoints.json`；
- 状态随时可查：`ros2 topic echo /omnifleet_t2/waypoints/status --once`。

## 7. 课上参数实验（学生可动手，只开 3 个）

Foxglove → Parameters 面板（白名单已限定范围）：

| 参数 | 当前值 | 建议范围 | 看什么效果 |
|---|---|---|---|
| `inflation_radius`（local/global costmap inflation_layer） | 0.3 m | 0.2–0.6 | 膨胀圈变厚变薄，绕障早晚 |
| `cost_scaling_factor`（同上） | 5.0 | 1–10 | 路径整体离墙远近 |
| `max_vel_x`（FollowPath/DWB） | 0.1 m/s | ≤0.3 | 车速直接变化 |

改完立即生效；要保留修改由教员调用 `/omnifleet_t2/nav2/save_parameters` 服务固化。其他参数（footprint、goal tolerance、加减速限制等）学生不要动。

---

## 8. 停止与关机

1. 取消当前导航目标：Foxglove 取消 / 航点面板 stop / `ros2 topic echo /omnifleet_t2/waypoints/status` 确认已停；
2. 停 Nav2：`sudo systemctl stop omnifleet-t2-navigation.service`（前台启动的按 Ctrl+C）；
3. 停 MOLA：在启动终端 Ctrl+C；
4. 常驻服务不用停，确认车辆静止后直接断电。

**急停 = 断底盘电源。微信 /stop 只取消 AI 任务，不是机器人急停。**

## 9. 出问题查哪里（索引到《T2实践课程操作指南.md》）

| 现象 | 查 |
|---|---|
| 连不上车 / 卡顿 / 多车互串 | 问题一（网络与 DOMAIN_ID=73） |
| 定位漂移、TF 跳变 | 问题二（自检清单与定位精度判定） |
| 相机无图像 | 问题三（相机服务检查） |
| 履带松脱、异响 | 问题四（行走机构检查） |
| 程序行为异常、文件被误改 | 问题五（服务重启 → backups 还原 → robot_doctor 验收） |
| 拉初始位姿没反应 | 问题七（重启导航再拉；仍无效记录上报） |
| 不知道参数在哪、能调什么 | 问题八 + 本指南第 7 节 |
| RViz/Foxglove 界面不会用 | 问题九 + 本指南第 3 节 |
